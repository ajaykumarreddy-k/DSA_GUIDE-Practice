0. Basics of Python

Topic: Language Overview

What is it:
Python is a high-level, interpreted, dynamically typed programming language.
Why use it:
It features an easy-to-read syntax, massive community libraries, and is widely adopted across web backend, data science, AI, and scripting automation.
How it works:
Code runs line-by-line via an interpreter — no manual compilation is needed to convert English-like syntax directly to binary.

Pipeline: Source Code (.py) -> Python Interpreter -> Binary Output

Topic: Setup & Run

To use the Python CLI, you'll need terminal access. Run the following commands:

1. Variables & Scope

Topic: Definitions & Architecture

Variable:
Container that stores in the data. Under the hood, variables are labels pointing to memory addresses (pointers).
Static vs Dynamic:
Python is dynamically typed (e.g., a = 5). You do not need to explicitly declare types like in C++ (int a = 5;).
Scope Details:
Scope dictates where a variable is accessible (Local and Global). Python resolves scope locally first, then globally (LEGB rule).
x = 10          # int
name = "Alice"  # str
a = b = c = 0       # all point to same value
x, y, z = 1, 2, 3   # unpacking — assign multiple at once

# Scope Implementation
g = "I am global"    # accessible everywhere

def demo():
    l = "I am local"    # only inside this function
    global g            # keyword to access/modify global
    g = "modified"

demo()
print(g)   # Outputs: "modified"

4. Core Logic Problems

Topic: Classic Algorithms

# 1. Prime Number Check
def is_prime(n):
    if n < 2: return False
    for i in range(2, int(n**0.5) + 1):
        if n % i == 0: return False
    return True

# 2. Factorial (Recursive)
def factorial(n):
    if n == 0 or n == 1: return 1
    return n * factorial(n - 1)

# 3. Armstrong Number (e.g., 153 = 1^3 + 5^3 + 3^3)
def is_armstrong(n):
    digits = str(n)
    power = len(digits)
    return n == sum(int(d)**power for d in digits)

# 4. Fibonacci Series
def fibonacci(n):
    a, b = 0, 1
    for _ in range(n):
        print(a, end=" ")
        a, b = b, a + b

# 5. Array Left/Right Rotation
a = [1, 2, 3, 4, 5]
k = 2 # Rotations
print("Left:", a[k:] + a[:k])
print("Right:", a[-k:] + a[:-k] if k else a)

Topic: Map, Filter, Reduce

Functional programming tools to process iterables efficiently without explicit loops.

from functools import reduce
nums = [1, 2, 3, 4, 5]

# map(function, iterable) - Apply function to every item

Topic: String Reversal Methods

Common interview question solved via 6 different methodologies:

s = "Python"
# 1. Slicing (Best & Fastest)
print(s[::-1])

# 2. Built-in
print("".join(reversed(s)))

# 3. Iteration
rev = ""
for char in s: rev = char + rev

# 4. Recursion
def rev_rec(s): return s if len(s)==0 else rev_rec(s[1:]) + s[0]

# 5. Stack (LIFO)
stack = list(s); rev = ""
while stack: rev += stack.pop()

# 6. Two-Pointer Approach
s_list = list(s)
l, r = 0, len(s)-1
while l < r:
    s_list[l], s_list[r] = s_list[r], s_list[l]
    l += 1; r -= 1

6. Object Oriented Programming (OOP)

Topic: Core Concepts

Class:
A template or blueprint used to create objects.
Object:
An instance of a class occupying memory.
Methods/Attributes:
Attributes are properties/variables. Methods are functions defined inside the class.
Constructors (__init__):
Special methods used to create an object automatically. Used to enter mandatory details. Types include parameterized and default.
self Keyword:
Refers to the current object instance. Used to differentiate between class attributes and local parameters.

Topic: The 4 Pillars

Encapsulation:
Bundling data and methods into a single unit. Uses Access Modifiers: Public (visible), Protected (_, visible to subclasses), Private (__, hidden).
Polymorphism:
Same method behaving differently.
• Method Overriding (Runtime): Child class alters parent method.
• Method Overloading (Compile-time): Same method, different parameters (handled via defaults in Python).
Inheritance:
Parent → Child relationship. Types: Single, Multiple, Multilevel, Hierarchical, Hybrid. Utilizes the super() function to call parent constructors/methods.
Abstraction:
Hiding internal implementation details (e.g., exposing frontend UI while hiding backend logic).

Topic: Magic (Dunder) Methods

Methods surrounded by double underscores. Used for Operator Overloading and core behaviors.

class Session:
    def __init__(self, chairs):
        self.chairs = chairs

    # Operator Overloading for '+'
    def __add__(self, other):
        return Session(self.chairs + other.chairs)

    # String representation (what prints out)
    def __str__(self):
        return f"Total Chairs: {self.chairs}"

s1 = Session(10)
s2 = Session(20)
print(s1 + s2) # Outputs: Total Chairs: 30

7. Advanced Python Concepts

Topic: Memory & References (Copying)

Assignment (=):
Does NOT copy. Both variables point to the same memory object.
Shallow Copy:
Creates a new outer container, but nested elements still reference the original.
Deep Copy:
Creates a completely independent clone at all nested levels.
import copy
original = [[1, 2], [3, 4]]

shallow = copy.copy(original)
deep = copy.deepcopy(original)

shallow[0][0] = 99
print(original)  # [[99, 2], [3, 4]] -> Affected by shallow copy
print(deep)      # [[1, 2], [3, 4]]  -> Completely safe

Topic: Generators & Decorators

Generators:
Functions using yield. They pause execution, returning values one at a time. Extremely memory efficient for large datasets.
Decorators:
Functions that take another function as input, add functionality, and return it. Signified by @decorator_name.
# Generator
def count_up(n):
    for i in range(1, n+1):
        yield i  # Yields value, pauses function

# Decorator
def my_logger(func):
    def wrapper():
        print("Starting execution...")
        func()
        print("Ending execution.")
    return wrapper

@my_logger
def say_hello():
    print("Hello!")

Topic: Global Interpreter Lock (GIL)

What is the GIL:
A mutex in CPython that prevents multiple native threads from executing Python bytecodes at once.
The Impact:
Python threads cannot achieve true parallelism on multi-core CPUs. For true parallel CPU-bound tasks, you must use the multiprocessing module instead of threading.

Topic: Sorting & Searching Implementations

Below is an implementation of Binary Search and Quick Sort:

# Binary Search - O(log n) Time | Array MUST be sorted
def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target: return mid
        elif arr[mid] < target: low = mid + 1
        else: high = mid - 1
    return -1

# Quick Sort - O(n log n) Time | O(n) Space (in this simplistic form)
def quick_sort(arr):
    if len(arr) <= 1: return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + middle + quick_sort(right)

Topic: Complexity Reference

Algorithm Description Best Case Worst Case
Linear Search Checks every element sequentially. O(1) O(n)
Binary Search Divides a sorted array in half repeatedly. O(1) O(log n)
Bubble Sort Swaps nearby elements repeatedly. O(n) O(n²)
Quick Sort Uses a pivot to partition the array (Fastest). O(n log n) O(n²)
Merge Sort Divide and conquer approach. O(n log n) O(n log n)
Tim Sort Hybrid of Merge + Insertion sort. O(n) O(n log n)

11. DBMS & Architecture

Topic: DBMS Overview

What is a DBMS:
A Database Management System (DBMS) is software that manages databases, helping you store, organize, update, retrieve, and keep data safe.
Analogy:
Think of a DBMS like an organized cupboard in your home.
• Files = clothes
• Shelves = tables
• Cupboard = database
• You = user
• Locks = security
Without a DBMS, data becomes a messy wardrobe where you throw clothes everywhere!

Topic: Types of DBMS

Stores data in tables (rows & columns). High consistency and structured schemas.

MySQL, PostgreSQL
2. Hierarchical

Organized in a tree-like parent-child structure where nodes have one parent.

IBM IMS
3. Network

Graph-like structure where nodes can have multiple parents. Used in telecom networks.

IDS, Integrated Data Store
4. NoSQL (Non-Relational)

Flexible, fast, handles unstructured/semi-structured data dynamically.

12. ER Model & Attributes

Topic: ER Model Basics

Definition:
The Entity-Relationship (ER) model is a conceptual schema diagram used to map database entities, properties, and connections before creating physical tables.
Entity:
A real-world object that exists independently and has unique properties. Examples: Student, Employee, Car, Order.

Topic: Attribute Types

Simple:
Atomic values that cannot be broken down further (e.g., Age, Salary).
Composite:
Properties that can be divided into smaller sub-attributes (e.g., Name → first_name, last_name).
Multivalued:
Can hold multiple values for a single entity (e.g., Phone Numbers, Emails). Represented as double ovals in ER.
Derived:
Calculated dynamically from another attribute rather than stored directly (e.g., Age derived from Date_of_birth).

Topic: Relationships & Cardinality

One-to-One (1:1):
One entity record maps to exactly one other. Example: One person has one passport.
One-to-Many (1:M):
One record maps to multiple records in the other table. Example: One teacher teaches many students.
Many-to-One (M:1):
Multiple records map to a single record. Example: Many employees report to one manager.
Many-to-Many (M:N):
Many records on both sides connect to each other. Requires a junction table. Example: Students take many courses, and courses have many students.

13. Database Keys

Topic: Key Types

Primary Key (PK):
Uniquely identifies a row in a table. It cannot be NULL and must contain unique values (e.g., StudentID).
Foreign Key (FK):
A column or group of columns that references a primary key in another table. It enforces referential integrity.
Composite Key:
A key that consists of more than one column to uniquely identify a row (e.g., OrderID + ProductID).
Candidate Key:
A minimal set of attributes that can uniquely identify a row. One becomes the Primary Key, while others become Alternate Keys (e.g., Email, Phone, RollNumber).
Super Key:
A set of one or more attributes that can uniquely identify a row. A super key can contain extra attributes that are not strictly necessary (e.g., StudentID + Email).

14. Normalization (1NF, 2NF, 3NF, BCNF)

Topic: Goal & Objective

Objective:
Normalization is a systematic data design process used to remove data duplicates (redundancy), reduce storage space, prevent consistency anomalies, and optimize index lookups.

Topic: First Normal Form (1NF)

Rule: Every column must contain atomic (single) values. No repeating groups.

❌ NOT in 1NF (Repeating Groups)
IDNamePhone
1Alex9876, 7654, 1234
✔ Convert to 1NF (Atomic Values)
IDNamePhone
1Alex9876
1Alex7654
1Alex1234

Topic: Second Normal Form (2NF)

Rule: Must be in 1NF, and all non-key columns must fully depend on the entire Primary Key. No partial dependency (non-key depending on only part of a composite primary key).

❌ NOT in 2NF

Primary Key: (OrderID, ProductID)

OrderID*ProductID*ProductName
10P22Laptop

ProductName depends only on ProductID (partial PK), not OrderID!

✔ Split Into Two Tables (2NF)

Order Table:

OrderID*ProductID*
10P22

Product Table:

ProductID*ProductName
P22Laptop

Topic: Third Normal Form (3NF)

Rule: Must be in 2NF, and no non-key columns can depend on other non-key columns. No transitive dependency (A → B → C).

❌ NOT in 3NF
StudentID*DeptIDDeptName
101D50CSE

DeptName depends transitively on DeptID, which is not a primary key.

✔ Split Into Two Tables (3NF)

Student Table:

StudentID*DeptID
101D50

Department Table:

DeptID*DeptName
D50CSE

Topic: Boyce-Codd Normal Form (BCNF)

Definition:
A stronger version of 3NF. For every functional dependency X → Y, X MUST be a Super Key of the table.
Difference:
3NF allows X → Y if Y is a prime attribute. BCNF strictly forbids this.

Topic: Normal Form Cheat Sheet

Normal Form Goal / Removes Primary Constraint
1NF Repeating groups & non-atomic data Atomic values inside every cell
2NF Partial functional dependencies Full dependency on the Primary Key
3NF Transitive dependencies (A → B → C) Non-key columns depend only on the Primary Key
BCNF Non-key determinants Determinant X in X → Y must be a Super Key

15. ACID Transaction Properties

Topic: The ACID Rules

Transactions must adhere to the ACID principles to ensure data safety, even under unexpected power failures or logical crashes.

A — Atomicity:
"All or Nothing". A transaction succeeds completely or rolls back entirely to leave data untouched.
Example: In a bank transfer, money must be successfully debited AND credited. If one fails, the entire transaction rolls back.
C — Consistency:
Ensures the database moves from one valid state to another, enforcing all schema constraints.
Example: Account balances cannot become negative unless explicitly allowed by system rules.
I — Isolation:
Multiple concurrent transactions execute independently without interfering with each other's uncommitted data.
Example: If two customers try to book the last available seat simultaneously, the system serializes execution so only one succeeds.
D — Durability:
Once a transaction commits, the changes are saved permanently in non-volatile storage and will survive power failures.
Example: A system power outage right after a successful booking does not wipe out the transaction.

16. SQL Joins & Commands

Topic: Joins Catalog

INNER JOIN:
Returns only rows that have matching values in both tables.
LEFT JOIN:
Returns all records from the left table, plus matching records from the right table. Matches without pairs yield NULL on the right side.
RIGHT JOIN:
Returns all records from the right table, plus matching records from the left table. Matches without pairs yield NULL on the left side.
FULL OUTER JOIN:
Returns all records when there is a match in either left or right tables. Combines Left and Right join results.
CROSS JOIN:
Returns the Cartesian product of the two tables — combining every row of the first table with every row of the second.
SELF JOIN:
A table joined with itself (useful for representing employee-manager hierarchies).
NATURAL JOIN:
Automatically joins tables based on columns with identical names and data types.
EQUI JOIN:
Uses equality operators (=) in the join condition (similar to INNER JOIN).
NON-EQUI JOIN:
Uses comparison operators other than equality (e.g., <, >, BETWEEN) to evaluate join logic.

Topic: SQL Command Sub-Languages

DQL (Query):
Used to retrieve records from the database.
• Keywords: SELECT, DISTINCT, FROM, WHERE, ORDER BY, GROUP BY, HAVING, LIMIT
DML (Manipulation):
Used to add, modify, or delete data records.
• Keywords: INSERT INTO, UPDATE, DELETE, MERGE

Used to create, modify, or destroy table structures.
• Keywords: CREATE, ALTER, DROP, TRUNCATE, RENAME
TCL (Transaction):
Used to manage ACID transaction states.
• Keywords: COMMIT, ROLLBACK, START TRANSACTION, SAVEPOINT

Topic: SQL Constraints

Constraints apply rules to the columns to ensure structural validity.

  • PRIMARY KEY: Enforces unique non-null values.
  • FOREIGN KEY: Enforces referential ties.
  • UNIQUE: Enforces unique column values.
  • NOT NULL: Enforces that columns cannot have blank data.
  • CHECK: Enforces customized boolean boundaries (e.g., marks BETWEEN 0 AND 100).
  • DEFAULT: Adds default values when empty.
  • AUTO_INCREMENT: Automatically bumps numeric IDs sequentially.

Topic: Execution Order

While we write SQL starting with SELECT, the engine processes keywords in this strict order:

1. FROM → 2. WHERE → 3. GROUP BY → 4. HAVING → 5. SELECT → 6. ORDER BY → 7. LIMIT

19. Self-Introduction Formula

Topic: Universal Delivery Rules

Structure:
1. Greeting & Name → 2. Current Status → 3. Education → 4. Core Skills & Tech → 5. Projects/Internships → 6. Work Style/Strengths → 7. Professional Goal.
Rules:
Speak slowly, avoid sounding memorized, maintain eye contact, and never include personal story items, hobbies, or family background details unless explicitly asked.

Topic: Core Formats

1-Minute Short Intro

"Good morning, I’m [Name]. I’m a recent graduate in [Branch] with a strong foundation in [Core Tech]. I have hands-on experience through academic projects where I focused on [Specific Work/Feature]. I am a dedicated and quick learner who enjoys problem-solving. I am now looking for an opportunity to grow professionally, learn from experienced team members, and add value to the organization."

2-Minute In-Depth (Manager Round)

"Good morning, my name is [Name]. I completed my graduation in [Branch] at [College]. During my studies, I focused on building strong fundamentals in [Tech stack], database operations, and data structures. I worked on a project named [Project Name] where I was responsible for [Specific Role, e.g., coding database logic, integrating APIs]. This helped me understand real-world troubleshooting and collaborative debugging. I’m a highly disciplined and adaptable person with a growth mindset. I am seeking an opportunity where I can take responsibility, contribute to production pipelines, and refine my skills as an engineer."

Topic: Adjectives and Keywords

Upskilling:
Quick learner, Adaptable, Curious, Continuous learner
Work Style:
Disciplined, Consistent, Reliable, Dedicated, Accountable
Thinking:
Analytical, Structured thinker, Detail-oriented, Logical approach
Banned Words:
Never call yourself an "expert", "master", "perfect", or "genius". It sounds arrogant. Instead, describe your capabilities with evidence of your projects.

20. HR Interview Questions

Topic: Core HR Prep

Why should we hire you?
Golden Structure: Acknowledge lack of corporate years → Highlight core fundamentals → Emphasize strong learning attitude → Align with company goals.
"As a fresher, I bring solid programming fundamentals and a highly adaptive mindset. I am eager to learn and can quickly pick up your production stack, contributing effectively under guidance."
What is your weakness?
Structure: Real but safe weakness + Immediate action.
"I sometimes spend extra time ensuring accuracy, which can slow me down. To manage this, I have started time-boxing my tasks and setting strict personal micro-deadlines."
Salary Expectations?
Structure: Growth priority → Flexible.
"As a fresher, my main priority is learning, getting practical exposure, and growing with the team. I am comfortable with the company's standard package and open to discussion."

21. Managerial Scenarios

Topic: Situational Frameworks

1. Production Bug:
Q: What if your code causes a production failure?
Approach: Ownership → Rollback → Root Cause → Prevention.
"I will immediately own up to the issue, collaborate with the ops team to rollback to the last stable deployment, debug the root cause locally, submit a fix with robust test cases, and document the learnings to prevent future occurrences."
2. Disagreement:
Q: How do you handle a tech disagreement with a teammate?
Approach: Professionalism → Data-driven metrics → Simplicity → Alignment.
"I will remove emotions from the discussion, compare both approaches objectively using metrics like readability, complexity, and implementation effort. If we remain split, I will seek advice from a senior or agree to back the team’s choice fully once a decision is finalized."
3. Stuck on a Task:
Q: What do you do if you are stuck on a technical blocker?
Approach: Structured self-help (documentation, debuggers) → Time-box (30-60 mins) → Seek senior guidance with structured context.
"I will research, check logs/documentation for 45 minutes. If I still cannot solve it, I will prepare a concise summary of what I tried and ask a teammate or senior for help, respecting their time."
